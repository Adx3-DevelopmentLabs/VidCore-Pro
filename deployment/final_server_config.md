# إعدادات السيرفر النهائية لمشروع VidCore-Pro (World-Class Edition)

هذا الدليل يحتوي على الإعدادات المثالية لتشغيل النسخة الأقوى من VidCore-Pro على منصات الاستضافة السحابية مثل Render و Railway.

## المتغيرات البيئية الأساسية (Environment Variables)

هذه المتغيرات يجب إضافتها في لوحة تحكم السيرفر (Render أو Railway) لضمان عمل جميع الميزات الجديدة (الذكاء الاصطناعي، الترجمات، الجودات المتعددة، وتكامل TMDB).

| المتغير (Variable) | القيمة المقترحة (Value) | الوصف (Description) |
| :--- | :--- | :--- |
| `PORT` | `3000` | المنفذ الذي سيعمل عليه التطبيق. |
| `NODE_ENV` | `production` | يخبر Node.js بأن التطبيق في بيئة الإنتاج لتحسين الأداء. |
| `CACHE_TTL` | `86400` | مدة بقاء البيانات في الذاكرة المؤقتة بالثواني (86400 = 24 ساعة). |
| `MAX_WORKERS` | `15` | عدد الخيوط المتزامنة (Threads) للتحقق من الروابط (زد الرقم إذا كان سيرفرك قوياً). |
| `ENABLE_HARDWARE_ACCEL` | `false` | اجعلها `true` فقط إذا كانت خطة الاستضافة تدعم معالجة الرسوميات (GPU). |
| `LOG_LEVEL` | `info` | مستوى تسجيل الأخطاء (يمكن تغييره إلى `error` لتقليل السجلات في الإنتاج). |
| `TMDB_API_KEY` | `مفتاحك_هنا` | **(مهم جداً)** مفتاح API الخاص بك من موقع TMDB لجلب بيانات الأفلام والمسلسلات. |

## إعدادات منصة Render

1.  **نوع الخدمة:** Web Service.
2.  **بيئة التشغيل (Runtime):** Docker (سيقوم Render بقراءة ملف `Dockerfile` تلقائياً).
3.  **أمر البناء (Build Command):** اتركه فارغاً (Docker يتكفل بذلك).
4.  **أمر التشغيل (Start Command):** `pnpm start`
5.  **مسار فحص الصحة (Health Check Path):** `/api/health` (يساعد Render على معرفة أن سيرفرك يعمل).
6.  **الخطة المقترحة:** خطة `Standard` أو أعلى لضمان أداء ممتاز لمحرك `Smart Resolver` وعمليات `yt-dlp`.

## إعدادات منصة Railway

1.  **طريقة النشر:** Deploy from GitHub Repo.
2.  **بيئة التشغيل:** سيقوم Railway باكتشاف `Dockerfile` وبناء المشروع تلقائياً.
3.  **أمر التشغيل (Start Command):** `pnpm start` (يمكن إضافته في إعدادات الخدمة إذا لزم الأمر).
4.  **الخطة المقترحة:** الخطة المدفوعة (Developer Plan) موصى بها بشدة لأن عمليات استخراج الروابط وفك التشفير تتطلب ذاكرة (RAM) ومعالجة (CPU) جيدة.

## ملاحظات هامة للأداء الأقصى

*   **الذاكرة (RAM):** محرك `Smart Resolver` وعمليات `yt-dlp` تستهلك ذاكرة. يُنصح بسيرفر لا يقل عن 1GB RAM، والأفضل 2GB فما فوق.
*   **تحديث yt-dlp:** ملف `Dockerfile` مصمم لجلب أحدث نسخة من `yt-dlp` عند كل عملية بناء (Build). يُنصح بإعادة بناء المشروع (Redeploy) كل فترة لضمان الحصول على أحدث التحديثات لتجاوز حمايات المواقع.
